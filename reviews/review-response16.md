Updated to 0.11.0. In response to the [last review](https://github.com/ramensoftware/windhawk-mods/pull/5331#issuecomment-5930433219):

- **Hook-install race:** both late-load paths now atomically claim installation before symbol resolution, including failed attempts.
- **Cache allocation and settings:** the outermost path-cache scope frees its string buffer. Side layers are limited to 1–2, the unused third rectangle is removed, and the roundness cross-reference is corrected.
- **Blocking title reads:** titles now use `InternalGetWindowText`, returning empty on failure. The tool-window filter also avoids `GetWindowTextLengthW`.
- **Click-path identity lookup:** clicks still request fresh identity, but metadata resolution now runs on the focus worker. The UI captures target data; serials, HWND/PID validation and deadlines reject superseded or stale results. A deadline cannot cancel an OS call already in progress.

The unbounded unload wait remains intentional: the DLL must not unload while its worker or callbacks can still execute. A hung worker API or UI dispatcher can therefore delay unloading. Registry desktop-ID lag and the noted Frame/Full caching and fallback-contour limitations remain unchanged.

Calculator testing also exposed two separate preview issues:

1. **Wrong window identity:** for immersive task items, `GetAppWindow` can identify the app content window rather than the frame tracked by foreground recency. Preview matching now uses `GetThumbnailWindow`, which provides the presented frame HWND on the tested build. Ordinary Win32 preview matching and icon metadata keep their existing getters.
2. **Missing activation notification:** an independent observer recorded Calculator becoming foreground and receiving keyboard focus without a foreground WinEvent, while a shell activation notification did arrive. The existing focus worker now also receives `HSHELL_WINDOWACTIVATED` / `HSHELL_RUDEAPPACTIVATED` through a hidden, nonactivating window. Both notification paths validate actual foreground; background creation and attention do not earn recency, and duplicates preserve focus deadlines. The temporary polling workaround and diagnostic hooks are removed. The cause of the missing WinEvent remains unknown; the shell API also has a documented compatibility caveat.
